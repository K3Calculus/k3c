## Key Distinctions

### K3 vs K3d

K3d is K3 where every distribution is a point (`∀s,e: T(s,e) = δ(s')`). K3d provides the strongest replay guarantee (no ω needed) and is the right choice when all causes are modeled. K3 is needed when the system has significant unmodeled causes — its distributions represent fields of potential, not randomness.

### K3 vs TLA+

K3 is more operational (explicit Apply semantics), TLA+ is more declarative (next-state relations). K3 lacks native liveness (addressed by K3ᵗ). TLA+ has more mature tooling for model checking. K3 provides explicit composition operators (<||>, <->), while TLA+ uses conjunction. K3's `why` pattern provides first-class rejection reasons; TLA+ has no equivalent.

### K3 vs Event Sourcing

K3 formalizes what event sourcing does in practice, adding explicit guards, invariants, and composition operators. Event sourcing systems are K3 systems with an append-only event log — K3 makes the implicit rules explicit and verifiable.

### K3 vs State Machines

K3 generalizes state machines with arbitrary state spaces (not just finite enums), first-class invariants, and algebraic composition. Any finite state machine is a K3 system with finite S and E.

### K3 vs Actor Model

K3 is single-system focused; composition is explicit via <||> and <->. Actors handle distribution natively but lack formal invariants. Actor supervision trees map to K3 bridge modes (Synchronous ≈ linked, BestEffort ≈ supervised).

### K3 vs Petri Nets

Petri nets use token-based state and firing rules. K3 generalizes this: tokens become arbitrary state, firing rules become guards, and K3 adds invariants and projections. Petri net composition maps to K3's <||>.

### K3 vs Process Algebra

Process algebras (CCS, CSP, π-calculus) focus on communication and concurrency. K3 focuses on causality within a single system and uses bridges for cross-system communication. Bisimulation equivalence from process algebra applies to K3 systems that share the same observable behavior.

### Formalism Embedding Table

| Formalism                  | K3 Relationship                               |
| -------------------------- | --------------------------------------------- |
| Finite State Machines      | K3d with finite S, E                          |
| Labeled Transition Systems | K3d without G, N, P                           |
| Petri Nets                 | K3d with token-based S, firing rules as G     |
| Event Sourcing             | K3d with append-only event log                |
| Actor Model                | K3d with message-based E, actor state as S    |
| TLA+ (safety fragment)     | K3d with temporal invariants                  |
| Markov Chains              | K3 with T → Dist(S), no guards, no invariants |
| Stochastic Processes       | K3 with continuous-support distributions      |

**Expressiveness hierarchy:**

```text
FSM ⊂ LTS ⊂ K3d ⊂ K3
Markov Chains ⊂ K3  (K3 adds guards, invariants, composition, causal interpretation)
```

# 2. Cross-Domain Examples

K3's universality is demonstrated by its ability to model systems across radically different domains. The following examples show that causality — and hence K3 — underlies physics, chemistry, and geometry.

**Note:** These examples use K3d (deterministic) transitions, as they model systems with complete causal knowledge. For domains with significant unmodeled causes (e.g., population dynamics, financial markets), general K3 with distributional transitions is more appropriate — see K3q.Calc.md for a comprehensive example.

## 2.1 Classical Mechanics (Point Particle)

A discretized model of Newtonian mechanics:

```text
K3_Particle = (S, S₀, E, G, T, N, P)

S = {
    position: Vector3,          // (x, y, z)
    velocity: Vector3,          // (vx, vy, vz)
    mass: ℝ⁺
}

S₀ = { position: (0, 0, 0), velocity: (0, 0, 0), mass: 1.0 }

E = ApplyForce(force: Vector3, dt: ℝ⁺)    // Force applied for time interval dt
    | Tick(dt: ℝ⁺)                         // Time evolution without external force

G(s, ApplyForce(f, dt)) = (dt > 0, "Time step must be positive")
G(s, Tick(dt)) = (dt > 0, "Time step must be positive")

T(s, ApplyForce(f, dt)) =
    let acceleration = f / s.mass in              // F = ma → a = F/m
    let new_velocity = s.velocity + acceleration * dt in
    let new_position = s.position + s.velocity * dt in
    { ...s, position: new_position, velocity: new_velocity }

T(s, Tick(dt)) =
    { ...s, position: s.position + s.velocity * dt }

N(s) = (s.mass > 0, "Mass must be positive")

P = {
    kinetic_energy: s → 0.5 * s.mass * |s.velocity|²,
    momentum: s → s.mass * s.velocity
}
```

**Note:** This is Euler integration. Higher-order integrators (Verlet, RK4) would use more complex transitions but the same K3 structure.

## 2.2 Chemical Reaction Network

Modeling chemical reactions as state transitions:

```text
K3_Chemistry = (S, S₀, E, G, T, N, P)

S = {
    concentrations: Map<Species, ℝ⁺>,   // [A], [B], [C], ...
    temperature: ℝ⁺,                     // Kelvin
    volume: ℝ⁺                           // Liters
}

S₀ = { concentrations: {H2: 2.0, O2: 1.0, H2O: 0.0}, temperature: 298, volume: 1.0 }

E = React(reaction: Reaction)
    // Reaction = { reactants: Map<Species, ℕ>, products: Map<Species, ℕ>, rate: ℝ⁺ }
    // Example: 2H₂ + O₂ → 2H₂O

G(s, React(r)) =
    let sufficient = ∀(species, count) ∈ r.reactants:
        s.concentrations[species] ≥ count * epsilon in
    (sufficient, "Insufficient reactants")

T(s, React(r)) =
    let new_conc = s.concentrations
        .subtract(r.reactants)           // Consume reactants
        .add(r.products) in              // Produce products
    { ...s, concentrations: new_conc }

N(s) = (
    ∀species: s.concentrations[species] ≥ 0,
    "Concentrations cannot be negative"
)

P = {
    total_mass: s → Σ(s.concentrations[sp] * molecular_weight(sp)),
    gibbs_energy: s → compute_gibbs(s)
}
```

**Conservation:** The invariant ensures non-negative concentrations. Mass conservation emerges from balanced reaction equations (total_mass projection remains constant for balanced reactions).

## 2.3 Euclidean Geometry (Compass and Straightedge)

Geometric construction as a K3 system:

```text
K3_Geometry = (S, S₀, E, G, T, N, P)

S = {
    points: Set<Point>,                  // Named points in the plane
    lines: Set<Line>,                    // Lines through two points
    circles: Set<Circle>                 // Circles with center and radius point
}

Point = (name: String, x: ℝ, y: ℝ)
Line = (p1: Point, p2: Point)
Circle = (center: Point, radius_point: Point)

S₀ = { points: {}, lines: {}, circles: {} }

E = PlacePoint(name: String, x: ℝ, y: ℝ)
    | DrawLine(p1: String, p2: String)
    | DrawCircle(center: String, radius_point: String)
    | Intersect(obj1: Object, obj2: Object)

G(s, PlacePoint(name, _, _)) = (name ∉ s.points.names, "Point name already exists")
G(s, DrawLine(p1, p2)) = (p1 ∈ s.points ∧ p2 ∈ s.points ∧ p1 ≠ p2, "Need two distinct points")
G(s, DrawCircle(c, r)) = (c ∈ s.points ∧ r ∈ s.points ∧ c ≠ r, "Need distinct center and radius point")
G(s, Intersect(o1, o2)) = (o1 ∈ s ∧ o2 ∈ s, "Objects must exist")

T(s, PlacePoint(name, x, y)) = { ...s, points: s.points ∪ {(name, x, y)} }
T(s, DrawLine(p1, p2)) = { ...s, lines: s.lines ∪ {Line(p1, p2)} }
T(s, DrawCircle(c, r)) = { ...s, circles: s.circles ∪ {Circle(c, r)} }
T(s, Intersect(o1, o2)) =
    let new_points = compute_intersections(o1, o2) in
    { ...s, points: s.points ∪ new_points }

N(s) = (
    ∀line ∈ s.lines: line.p1 ∈ s.points ∧ line.p2 ∈ s.points,
    "Lines must reference existing points"
)

P = {
    point_count: s → |s.points|,
    constructible: p → is_constructible_from(p, s)
}
```

**Insight:** The classical impossibility results (trisecting an angle, squaring the circle) correspond to unreachable states — no event sequence from S₀ can construct those points.

## 2.4 Universality Observation

These examples demonstrate that K3 captures:

| Domain      | State                  | Event             | Guard                  | Transition           | Invariant             |
| ----------- | ---------------------- | ----------------- | ---------------------- | -------------------- | --------------------- |
| Mechanics   | Position, velocity     | Force application | Physical validity      | Newton's laws        | Conservation laws     |
| Chemistry   | Concentrations         | Reactions         | Sufficient reactants   | Stoichiometry        | Mass conservation     |
| Geometry    | Points, lines, circles | Constructions     | Constructibility rules | Geometric operations | Referential integrity |
| Computation | Lambda terms           | β-reduction       | Valid redex            | Substitution         | Well-formedness       |

The pattern is universal: **State** holds what exists, **Events** perturb it, **Guards** constrain what's possible, **Transitions** define how perturbation produces change, **Invariants** ensure consistency, and **Projections** reveal derived properties.

# 3. Extended Examples

## 3.1 Distributed Lock Service

A more complex example demonstrating composition and bridges.

**Determinism Note:** This example passes timestamps in event payloads to ensure K3 determinism (Axiom 1). The event source (external system, scheduler) provides the timestamp; K3 does not call `now()`.

```text
=== LockManager Universe ===

State (S):
    {
        locks: Map<ResourceId, LockState>,
        waiters: Map<ResourceId, Queue<ClientId>>
    }

    LockState = Free | Held(client: ClientId, expires: Timestamp)

Initial (S₀):
    { locks: {}, waiters: {} }

Events (E):
    Acquire(client: ClientId, resource: ResourceId, ttl: Duration, at: Timestamp)
    | Release(client: ClientId, resource: ResourceId, at: Timestamp)
    | Expire(resource: ResourceId, at: Timestamp)
    | Heartbeat(client: ClientId, resource: ResourceId, ttl: Duration, at: Timestamp)

Guards (G):
    G(s, Acquire(c, r, _, _)) =
        let lock = s.locks.get(r, Free) in
        (lock = Free ∨ lock.client = c, "Resource locked by another client")

    G(s, Release(c, r, _)) =
        let lock = s.locks.get(r, Free) in
        (lock ≠ Free ∧ lock.client = c, "Cannot release: not held by this client")

    G(s, Expire(r, at)) =
        let lock = s.locks.get(r, Free) in
        (lock ≠ Free ∧ lock.expires < at, "Lock not expired")

    G(s, Heartbeat(c, r, _, _)) =
        let lock = s.locks.get(r, Free) in
        (lock ≠ Free ∧ lock.client = c, "Cannot heartbeat: not held")

Transitions (T):
    T(s, Acquire(c, r, ttl, at)) =
        { ...s, locks: s.locks.set(r, Held(c, at + ttl)) }

    T(s, Release(c, r, _)) =
        { ...s, locks: s.locks.remove(r) }

    T(s, Expire(r, _)) =
        { ...s, locks: s.locks.remove(r) }

    T(s, Heartbeat(c, r, ttl, at)) =
        { ...s, locks: s.locks.set(r, Held(c, at + ttl)) }

Invariants (N):
    N(s) = (
        ∀r: at_most_one_holder(s.locks, r),
        "Resource cannot be held by multiple clients"
    )

Projections (P):
    held_count = s → s.locks.values.count(l → l ≠ Free)
    client_locks = client → (s → s.locks.filter((r, l) → l.client = client))


=== AuditLog Universe ===

State (S):
    { entries: List<AuditEntry> }

    AuditEntry = { timestamp: Timestamp, action: String, details: Map }

Events (E):
    Log(action: String, details: Map, at: Timestamp)

Guards (G):
    G(s, Log(_, _, _)) = (true, "")  // Always allowed

Transitions (T):
    T(s, Log(action, details, at)) =
        { entries: s.entries ++ [{ timestamp: at, action, details }] }

Invariants (N):
    N(s) = (s.entries.is_sorted_by(e → e.timestamp), "Entries must be ordered")


=== Composed Universe with Bridge ===

LockManager <->[audit_mapper, BestEffort] AuditLog

audit_mapper(before, event, after) = match event with
    | Acquire(c, r, _, at)  → Some(Log("ACQUIRE", {client: c, resource: r}, at))
    | Release(c, r, at)     → Some(Log("RELEASE", {client: c, resource: r}, at))
    | Expire(r, at)         → Some(Log("EXPIRE", {resource: r}, at))
    | Heartbeat(_, _, _, _) → None  // Don't log heartbeats
```

## 3.2 Saga with Compensation

```text
=== OrderSaga Universe ===

State (S):
    {
        order_id: OrderId,
        status: Pending | PaymentProcessing | InventoryReserving |
                Shipping | Completed |
                PaymentFailed | InventoryFailed | ShippingFailed |
                Compensating | Compensated,
        payment_ref: PaymentRef?,
        inventory_ref: InventoryRef?,
        shipping_ref: ShippingRef?,
        compensation_step: Int
    }

Events (E):
    // Forward flow
    StartPayment
    | PaymentSucceeded(ref: PaymentRef)
    | PaymentFailed(reason: String)
    | StartInventoryReserve
    | InventoryReserved(ref: InventoryRef)
    | InventoryFailed(reason: String)
    | StartShipping
    | ShippingStarted(ref: ShippingRef)
    | ShippingFailed(reason: String)
    | Complete

    // Compensation flow
    | StartCompensation
    | CompensateShipping
    | CompensateInventory
    | CompensatePayment
    | CompensationComplete

Guards (G):
    // Forward flow guards
    G(s, StartPayment) = (s.status = Pending, "Must be pending")
    G(s, PaymentSucceeded(_)) = (s.status = PaymentProcessing, "Must be processing payment")
    G(s, PaymentFailed(_)) = (s.status = PaymentProcessing, "Must be processing payment")
    G(s, StartInventoryReserve) = (s.status = PaymentProcessing ∧ s.payment_ref ≠ None, "Payment must succeed first")
    G(s, InventoryReserved(_)) = (s.status = InventoryReserving, "Must be reserving inventory")
    G(s, InventoryFailed(_)) = (s.status = InventoryReserving, "Must be reserving inventory")
    G(s, StartShipping) = (s.status = InventoryReserving ∧ s.inventory_ref ≠ None, "Inventory must be reserved first")
    G(s, ShippingStarted(_)) = (s.status = Shipping, "Must be shipping")
    G(s, ShippingFailed(_)) = (s.status = Shipping, "Must be shipping")
    G(s, Complete) = (s.status = Shipping ∧ s.shipping_ref ≠ None, "Shipping must start first")

    // Compensation flow guards
    G(s, StartCompensation) = (s.status ∈ {PaymentFailed, InventoryFailed, ShippingFailed}, "Must be in failed state")
    G(s, CompensateShipping) = (s.status = Compensating ∧ s.shipping_ref ≠ None, "Has shipping to compensate")
    G(s, CompensateInventory) = (s.status = Compensating ∧ s.inventory_ref ≠ None ∧ s.shipping_ref = None, "Has inventory to compensate")
    G(s, CompensatePayment) = (s.status = Compensating ∧ s.payment_ref ≠ None ∧ s.inventory_ref = None, "Has payment to compensate")
    G(s, CompensationComplete) = (s.status = Compensating ∧ s.payment_ref = None, "All compensations done")

Transitions (T):
    // Forward flow transitions
    T(s, StartPayment) = { ...s, status: PaymentProcessing }
    T(s, PaymentSucceeded(ref)) = { ...s, payment_ref: Some(ref) }
    T(s, PaymentFailed(_)) = { ...s, status: PaymentFailed }
    T(s, StartInventoryReserve) = { ...s, status: InventoryReserving }
    T(s, InventoryReserved(ref)) = { ...s, inventory_ref: Some(ref) }
    T(s, InventoryFailed(_)) = { ...s, status: InventoryFailed }
    T(s, StartShipping) = { ...s, status: Shipping }
    T(s, ShippingStarted(ref)) = { ...s, shipping_ref: Some(ref) }
    T(s, ShippingFailed(_)) = { ...s, status: ShippingFailed }
    T(s, Complete) = { ...s, status: Completed }

    // Compensation flow transitions (reverse order)
    T(s, StartCompensation) = { ...s, status: Compensating }
    T(s, CompensateShipping) = { ...s, shipping_ref: None }
    T(s, CompensateInventory) = { ...s, inventory_ref: None }
    T(s, CompensatePayment) = { ...s, payment_ref: None }
    T(s, CompensationComplete) = { ...s, status: Compensated }

Invariants (N):
    N(s) = (
        valid_state_machine(s.status) ∧
        (s.status = Completed ⇒ all_refs_present(s)) ∧
        (s.status = Compensated ⇒ all_refs_reversed(s)),
        "Invalid saga state"
    )

// This saga would be bridged to Payment, Inventory, and Shipping systems
```
