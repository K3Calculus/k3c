# The Kulkarni Calculus (K3)

## A Universal Causal Calculus for System Design

**Version 0.1**

## Abstract

The **Kulkarni Calculus** (K3) is a minimal calculus for modeling discrete causal systems. Just as Lambda Calculus provides the foundation for computation and Relational Calculus provides the foundation for data, K3 provides a foundation for systems with explicit causality, temporal evolution, invariants, simulation, and composition.

K3 formalizes causality through a **7-tuple** of primitives and **three meta-operators**, sufficient to model any discrete causal system with decidable predicates and formal guarantees of safety.

The calculus is grounded in Samkhya philosophy's principle of **Ananta Shakti** (अनन्त शक्ति — infinite potential): every cause contains the infinite potential of its effects. The transition function produces not a single next state, but a **field of potential** — a distribution over possible states — representing the range of effects latent in the cause. What we observe as "randomness" is not ontological chance, but the manifestation of causes we have not modeled.

> **Core Doctrine:** *Design causality, and the system emerges.*

# 1. Introduction

## 1.1 Motivation

Traditional approaches to system design — state machines, event sourcing, actor models — lack a unifying formal foundation. Each provides useful abstractions but none offers a minimal, complete calculus from which system behaviors can be derived with formal guarantees.

K3 addresses this gap by treating **causality** as the primitive concept. Every system behavior is expressed as: *given this state and this event, what are the potential effects, and what must remain true of the transformation?*

A critical insight shapes the calculus: **no finite model captures all causes.** A bank account transition appears deterministic — deposit $100, balance increases by $100. But this is only because we have modeled every relevant cause. A weather system, a market, a population — these appear "random" not because reality rolls dice, but because causes exist that we have not included in our model.

K3 treats this as the general case. The transition function produces a **distribution** — a field of potential weighted by causal plausibility. When all causes are modeled, this distribution collapses to a single point, and K3 reduces to the familiar deterministic case (K3d). When causes remain unmodeled, the distribution has breadth, and the calculus reasons about the entire field of potential.

## 1.2 The Physics Analogy

K3 is a **physics engine for systems**. Just as physics engines model the physical world, K3 models any system as chains of cause and effect:

| Physics Engine    | K3                    |
| ----------------- | --------------------- |
| Particles         | Entities (in state)   |
| Forces            | Events                |
| Laws of motion    | Transitions           |
| Conservation laws | Invariants            |
| Wave function     | Distribution (Dist S) |
| Time evolution    | Simulation            |
| Measurement       | Projection            |
| Observation       | Sampling              |

The wave function analogy is deliberate. In quantum mechanics, the wave function represents the potential of a system; measurement collapses it to an observed value. In K3, the distribution represents the potential of a transition; sampling collapses it to an actual state. The analogy is structural, not physical — K3 does not model quantum phenomena — but it captures the same relationship between potential and actuality.

## 1.3 Design Principles

1. **Minimality**: No primitive can be derived from others
2. **Expressiveness**: Any discrete causal system with decidable predicates can be expressed
3. **Compositionality**: Systems combine algebraically
4. **Decidability**: Guards and invariants are computable predicates
5. **Causal completeness**: The distribution captures all potential effects given the modeled causes

## 1.4 Etymology

**Kulkarni Calculus** denoted as **K3** is derived from "Karma Kognitive Kit". The name **Karma** (कर्म) from Sanskrit means "action" or "deed" — the universal law of cause and effect. The calculus embodies this principle: *define causality, and behavior emerges*.

## 1.5 Philosophical Foundation

### Satkaryavada — The Effect Pre-Exists in the Cause

The Samkhya school of Indian philosophy provides a theory of causation called **Satkaryavada** (सत्कार्यवाद): the effect pre-exists in the cause. The pot exists latently in the clay before the potter shapes it. The curd is latent in the milk before fermentation begins.

This principle has a profound implication: **there is no ontological randomness.** Every effect arises from causes, whether we model those causes or not. What appears random is simply the manifestation of causes outside our model.

### Ananta Shakti — Infinite Potential

**Ananta Shakti** (अनन्त शक्ति — infinite potency) is the principle that Prakriti (primordial nature) contains infinite potential for manifestation. Every cause contains the latent potential for many effects; which effect manifests depends on the full configuration of causes, many of which may be unmodeled.

In K3, this principle takes concrete form: the transition function `T : S × E → Dist(S)` produces a distribution — a field of potential. The distribution does not represent "randomness." It represents **the range of effects that are causally plausible given what we know.** The peak of the distribution is where causal energy concentrates — the most likely outcome given our model. The tails represent outcomes requiring rare or unusual configurations of unmodeled causes.

When our causal model is complete — when we have modeled every relevant cause — the distribution collapses to a single point: `T(s, e) = δ(s')`. This is the deterministic case. The distribution has zero width because no causes remain unmodeled.

### Parinama — Validate the Transformation

**Parinama** (परिणाम) means outcome of *transformation* — the process by which cause becomes effect. When the transition produces a field of potential rather than a single state, the invariant must answer: **"Is this transformation valid?"**

The invariant does not check each possible outcome individually. The distribution is a single causal object — the transformation itself. Just as the clay either has the nature to become a pot or it does not, the transformation either satisfies the invariant or it does not. This is the Parinama Principle: **validate the transformation, not the points.**

```text
N : Dist(S) → Bool × String       "Is this transformation valid?"
```

## 1.6 Scope

K3 is designed for **discrete causal systems** — systems where:

- State is discrete (or discretized)
- Time advances in logical steps (event indices)
- Transitions produce distributions over states
- All predicates (guards, invariants) are decidable

K3 does **not** natively model:

- Continuous-time dynamics (use discretized time steps — see K3.Patterns)
- Liveness properties (see K3ᵗ extension)
- Higher-order systems that modify their own transitions (model as rules-in-state — see K3.Patterns)
- Concurrent event processing (use composition)

### Sequential Semantics

**K3 systems process events sequentially.** The `Apply` function defines an atomic state transition; there is no concurrent `Apply` in K3 semantics.

```text
Apply(s, e) → Dist(S) ∪ {⊥}     // Atomic: one event, one field of potential
Reduce(d, E*)                     // Sequential: events processed one at a time
```

For systems requiring concurrent event processing, model concurrent components as separate K3 systems and compose them:

```text
System = Component₁ <||> Component₂ <||> Component₃
```

Each component processes its events sequentially. Concurrency exists *between* components, mediated by bridges.

# 2. The Calculus

## 2.1 Definition

A K3 model is a **7-tuple**:

```text
K3 = (S, S₀, E, G, T, N, P)
```

## 2.2 The Seven Primitives

| Symbol | Name       | Sanskrit | Devanagari | Type                        | Description              |
| ------ | ---------- | -------- | ---------- | --------------------------- | ------------------------ |
| **S**  | State      | Avasthā  | अवस्था       | `Set`                       | The state space          |
| **S₀** | Initial    | Aarambha | आरम्भ       | `S₀ ∈ S`                    | The initial state        |
| **E**  | Event      | Ghatna   | घटना        | `Set`                       | The event space          |
| **G**  | Guard      | Rakshak  | रक्षक       | `S × E → Bool × String`     | Admissibility predicate  |
| **T**  | Transition | Chalan   | चलन        | `S × E → Dist(S)`           | Causal transformation    |
| **N**  | Invariant  | Niyama   | नियम        | `Dist(S) → Bool × String`   | Transformation validator |
| **P**  | Projection | Prakriti | प्रकृति       | `{name: S → R}` (+ lifting) | Derived computations     |

### Note on Projections

Projections unify derived computations and observable views. Both are pure functions from state to some output type:

```text
P = {
    name: String,
    fn: S → R,
    kind: Derived | Observable | Metric,  // Optional classification
    cache: Bool                            // Implementation hint
}
```

Projections lift to distributions: `P.name(d) = map(P.name, d)`.

## 2.3 Distributions — The Field of Potential

A **distribution** over S represents the field of potential — the range of effects latent in a cause, weighted by causal plausibility:

```text
Dist(S) = { d : S → [0, 1]  |  Σ_{s ∈ support(d)} d(s) = 1 }

support(d) = { s ∈ S | d(s) > 0 }
```

The weight `d(s)` represents the **causal plausibility** of state `s` given the modeled causes. Higher weight means the modeled causes point more strongly toward this outcome.

### Distribution Constructors

```text
// Point distribution — complete causal knowledge, one outcome certain
δ(s) : Dist(S)
δ(s)(s') = if s = s' then 1 else 0

// Uniform — equal causal plausibility across a set
uniform(A) : Dist(S)  where A ⊆ S, |A| < ∞
uniform(A)(s) = if s ∈ A then 1/|A| else 0

// Weighted — specified causal plausibilities
weighted([(s₁, w₁), ..., (sₙ, wₙ)]) : Dist(S)
weighted(pairs)(s) = wᵢ / Σwⱼ  if s = sᵢ for some i, else 0

// Bernoulli — binary potential
bernoulli(s_true, s_false, p) : Dist(S)
bernoulli(s_t, s_f, p)(s) = if s = s_t then p
                             else if s = s_f then 1-p
                             else 0

// Conditional — potential depends on a predicate
cond(predicate, d₁, d₂) : Dist(S)
cond(P, d₁, d₂)(s) = if P then d₁(s) else d₂(s)
```

### Distribution Operations

```text
// Expected value of a function over a distribution
E[f, d] = Σ_{s ∈ support(d)} d(s) · f(s)

// Map a function over support
map(f, d)(s') = Σ_{s : f(s) = s'} d(s)

// Bind (monadic — sequence two causal steps)
bind(d, f)(s') = Σ_{s ∈ support(d)} d(s) · f(s)(s')
    where f : S → Dist(S)

// Marginal (project distribution to subset of state)
marginal(d, π)(r) = Σ_{s : π(s) = r} d(s)

// Conditioning (Bayesian update — refine potential given observation)
condition(d, predicate)(s) =
    if predicate(s) then d(s) / Σ_{s' : predicate(s')} d(s')
    else 0
```

## 2.4 The Three Meta-Operators

| Symbol     | Name    | Sanskrit | Type                               | Description                    |
| ---------- | ------- | -------- | ---------------------------------- | ------------------------------ |
| **<\|\|>** | Compose | —        | `K3 × K3 → K3`                     | Parallel composition           |
| **<->**    | Bridge  | —        | `K3 × K3 × Mapper × Mode → Bridge` | Cross-system event propagation |
| **<?>**    | Samsara | संसार      | `K3 × E* → RunResult`              | Simulation & testing           |

## 2.5 Foundational Axioms

**Axiom 1 — Deterministic Potential.** `T` is a deterministic function. Given the same state and event, it always produces the **same distribution**. The field of potential is determined by the modeled causes; it does not vary between invocations.

```text
∀s ∈ S, e ∈ E: T(s, e) = T(s, e)    // Referentially transparent
```

**Axiom 2 — Totality.** `G`, `T`, `N` are total functions. Guards, transitions, and invariants are defined for all inputs.

```text
∀s ∈ S, e ∈ E: G(s, e) is defined
∀s ∈ S, e ∈ E: T(s, e) is defined
∀d ∈ Dist(S): N(d) is defined
```

**Axiom 3 — Closure.** The support of any transition result is a subset of S.

```text
∀s ∈ S, e ∈ E: support(T(s, e)) ⊆ S
```

**Axiom 4 — Initial Validity.** The initial state, lifted to a point distribution, satisfies the invariant.

```text
N(δ(S₀)) = (true, _)
```

**Well-Formedness.** Valid transformations of valid states produce valid transformations:

```text
∀s ∈ S, e ∈ E:
    N(δ(s)) = (true, _) ∧ G(s, e) = (true, _) ⇒ N(T(s, e)) = (true, _)
```

This is the fundamental proof obligation for every K3 system.

# 3. Operational Semantics

## 3.1 The Causal Step (Apply)

The fundamental operation in K3:

```text
Apply : S × E → Dist(S) ∪ {⊥}

Apply(s, e) =
    let (g_ok, g_reason) = G(s, e) in
    if ¬g_ok then ⊥[impossible(g_reason)]
    else
        let d = T(s, e) in
        let (n_ok, n_reason) = N(d) in
        if ¬n_ok then ⊥[violated(n_reason)]
        else d
```

The result is a distribution over successor states — a field of potential. The invariant validates the entire distribution (the transformation), not individual states.

```text
Guard checks: "Is this event admissible in this state?"
Transition:   "What is the field of potential?"
Invariant:    "Is this transformation valid?"
```

## 3.2 Execution Order

The Apply function defines a strict execution order:

```text
1. Pre-invariant check (optional, defense in depth)
2. Guard evaluation
3. Transition computation (produces distribution)
4. Post-invariant check (validates distribution)
5. Result: distribution or rejection
```

## 3.3 Pre-Invariant Check (Defense in Depth)

Implementations MAY check the invariant on the current state before processing:

```text
Apply_defended(s, e) =
    let (pre_ok, pre_reason) = N(δ(s)) in
    if ¬pre_ok then ⊥[corrupted(pre_reason)]      // Current state already invalid
    else Apply(s, e)                                // Normal flow
```

Pre-invariant failure indicates a bug — the system reached an invalid state. This is defense in depth, not normal flow.

## 3.4 Invariant Phases

Implementations may configure when invariants are checked:

| Phase | Checks           | Use Case                            |
| ----- | ---------------- | ----------------------------------- |
| Post  | After T only     | Normal operation (default)          |
| Both  | Before and after | Debug mode, defense in depth        |
| Pre   | Before T only    | Detect prior corruption             |
| None  | Never            | Performance mode (use with caution) |

## 3.5 Sampling — The Manifestation

To obtain a concrete state from the field of potential, the distribution must be **sampled**:

```text
Sample : Dist(S) × Ω → S

Sample(d, ω) = s    where s is drawn from d using ω
```

`Ω` (omega) represents the **unmodeled causes** — the causal variables not included in S that determine which potential manifests as actuality. In practice, Ω is implemented as an entropy source (PRNG, hardware RNG), but its *meaning* is: "the causes I haven't modeled."

**Sampled Apply** (for concrete execution):

```text
ApplySampled(s, e, ω) =
    let d = Apply(s, e) in
    if d = ⊥ then ⊥
    else Sample(d, ω)
```

**Important:** The invariant check happens *before* sampling. N validates the distribution — the field of potential — before any particular outcome manifests. A sampled state comes from a distribution that has already been approved as a valid transformation.

For systems with complete causal models (deterministic case), `T(s, e) = δ(s')` and `Sample(δ(s'), ω) = s'` for all ω. Sampling is trivial — the field of potential has exactly one point.

## 3.6 Reduction

**Distributional Reduce** (exact, tracks full field of potential):

```text
Reduce : Dist(S) × E* → Dist(S) ∪ {⊥}

Reduce(d, []) = d
Reduce(d, e :: es) =
    let d' = bind(d, λs. Apply(s, e)) in
    if d' = ⊥ then ⊥
    else Reduce(d', es)
```

This computes the exact posterior distribution — the field of potential after a sequence of events.

**Sampled Reduce** (concrete, single trajectory):

```text
ReduceSampled(s, [], ω) = s
ReduceSampled(s, e :: es, ω) =
    let (ω₁, ω₂) = split(ω) in
    let s' = ApplySampled(s, e, ω₁) in
    if s' = ⊥ then ⊥
    else ReduceSampled(s', es, ω₂)
```

**Deterministic Reduce** (special case when all distributions are points):

```text
ReduceDet(s, [], _) = s
ReduceDet(s, e :: es, _) =
    let d = Apply(s, e) in       // d = δ(s') for deterministic systems
    let s' = the_single_state(d) in
    ReduceDet(s', es, _)
```

This is the familiar reduction from the deterministic case (K3d), and is the most common in practice.

## 3.7 Simulation Modes

| Mode               | Tracks                    | Cost        | Use Case                               |
| ------------------ | ------------------------- | ----------- | -------------------------------------- |
| **Deterministic**  | Single state per step     | Linear      | Complete causal models (K3d)           |
| **Distributional** | Full `Dist(S)` per step   | Exponential | Exact analysis, small S                |
| **Monte Carlo**    | Single sampled trajectory | Linear      | Practical execution, partial knowledge |

**Monte Carlo Simulation:**

```text
MonteCarloSimulate(K3, events, n_runs, ω) =
    for i in 1..n_runs:
        ωᵢ = derive(ω, i)
        trajectory[i] = ReduceSampled(S₀, events, ωᵢ)
    return {
        trajectories: trajectory[1..n],
        distribution: empirical_distribution(final_states),
        statistics: compute_statistics(trajectories)
    }
```

## 3.8 Time Semantics

K3 uses **logical time**, not wall-clock time:

```text
time(s) = number of events processed to reach s
```

Logical time defines *ordering*, not duration. Real-time constraints can be modeled by encoding timestamps in event payloads and checking them in guards (see K3.Patterns).

## 3.9 Error Types

| Error                | Condition                                           |
| -------------------- | --------------------------------------------------- |
| `PreInvariantError`  | `N(δ(s)) = (false, reason)` — current state invalid |
| `GuardError`         | `G(s, e) = (false, reason)` — event not allowed     |
| `PostInvariantError` | `N(d) = (false, reason)` — transformation invalid   |
| `UnknownEventError`  | Event has no registered transition (strict mode)    |

# 4. Guards

Guards remain **deterministic and state-dependent**:

```text
G : S × E → Bool × String
```

Guards decide *whether* an event is admissible. This decision is based on the current state and the event, and it is always deterministic. If you want the admissibility decision to depend on unmodeled causes, model it as two events — a deterministic attempt and a transition with distributional outcome:

```text
// Instead of a "probabilistic guard":
E = AttemptAttack | AttackHit | AttackMiss

G(s, AttemptAttack) = (s.can_attack, "Cannot attack")
T(s, AttemptAttack) = weighted([
    ({ ...s, pending: Hit }, 0.7),
    ({ ...s, pending: Miss }, 0.3)
])
```

The *decision to attempt* is deterministic. The *outcome* reflects unmodeled causes.

### Guard Returns Bool × String

The guard returns a boolean and a reason string. The string explains *why* the event is rejected:

```text
G(s, Withdraw(amount)) = (
    s.balance ≥ amount ∧ amount > 0,
    if amount ≤ 0 then "Amount must be positive"
    else "Insufficient balance: " + s.balance + " < " + amount
)
```

# 5. Invariants — The Parinama Principle

## 5.1 The Central Idea

The transition produces a field of potential — a distribution over states. The invariant asks: **"Is this transformation valid?"**

```text
N : Dist(S) → Bool × String
```

N is a **total, deterministic** function from distributions to verdicts. Given the same distribution, it always returns the same answer. It may examine any property of the distribution: its support, its moments, its shape, its entropy, or any combination.

The Parinama Principle: the distribution is the transformation. N validates the *act of transforming*, not each possible consequence in isolation. One input (the distribution), one check, one answer.

## 5.2 Why This Matters

Consider a system where `T(s, MarketTick)` produces a distribution over possible portfolio values.

**Pointwise approach** (check each outcome): "Every possible portfolio value must be non-negative." This rejects all transitions where any outcome, however implausible, dips below zero.

**Distributional approach** (validate the transformation): "The expected portfolio value must remain positive and the 95th-percentile loss must not exceed the risk budget." This validates the nature of the transformation — its shape, its risk profile, its expected behavior.

For systems with complete causal knowledge (K3d), every distribution is a point `δ(s')`, and `N(δ(s'))` reduces to checking the single state `s'`. The Parinama Principle subsumes the deterministic case.

## 5.3 The `why` Pattern

N returns `Bool × String`. The string explains what about the transformation is invalid:

```text
N(d) = (false, "Expected return is -12%, below minimum -5%")
N(d) = (false, "Probability of negative balance exceeds threshold")
N(d) = (false, "Variance too high — unmodeled causes dominate")
```

These are reasons about the transformation, not about individual states.

## 5.4 Well-Formedness

For a K3 system to be well-formed:

```text
∀s ∈ S, e ∈ E:
    N(δ(s)) = (true, _) ∧ G(s, e) = (true, _) ⇒ N(T(s, e)) = (true, _)
```

Valid transformations of valid states must produce valid transformations.

# 6. Common Invariant Patterns

These are **recipes** for writing N functions, not modes to be selected. A single N may combine several patterns.

## 6.1 Pointwise (Certain)

Validate every state in the support:

```text
N_pointwise(d) = (
    ∀s ∈ support(d): check(s).ok,
    first_failing(d, check).why
)
```

**Use when:** Safety is absolute. No outcome may violate the constraint. This is the only pattern needed for systems with complete causal knowledge (K3d).

## 6.2 Probabilistic Threshold

```text
N_threshold(d, check, θ) = (
    Pr[check(s).ok | s ~ d] ≥ θ,
    "Invariant probability below threshold"
)
```

**Use when:** Some causal plausibility of violation is acceptable.

## 6.3 Expected Value

```text
N_expected(d, f, bound) = (
    E[f, d] ≥ bound,
    "Expected value below bound"
)
```

**Use when:** The central tendency matters more than any individual outcome.

## 6.4 Shape Constraints

These have no pointwise equivalent — they are genuinely distributional:

```text
// Variance bound (how much uncertainty from unmodeled causes)
N_variance(d, f, max_var) = (Var[f, d] ≤ max_var, "Variance exceeds limit")

// Support size (how many distinct outcomes are possible)
N_support(d, max_size) = (|support(d)| ≤ max_size, "Too many outcomes")

// Entropy bound (information-theoretic measure of causal uncertainty)
N_entropy(d, min_H, max_H) = (min_H ≤ H(d) ≤ max_H, "Entropy outside bounds")
```

## 6.5 Risk Metrics

```text
// Value at Risk
N_VaR(d, f, α, limit) = (VaR(f, d, α) ≥ limit, "VaR below limit")

// Conditional Value at Risk (expected shortfall)
N_CVaR(d, f, α, limit) = (CVaR(f, d, α) ≥ limit, "CVaR below limit")
```

## 6.6 Composite

```text
N(d) =
    let safe = ∀s ∈ support(d): s.balance ≥ 0 in
    let bounded_risk = Var[s → s.balance, d] ≤ max_risk in
    let positive_expected = E[s → s.balance, d] > 0 in
    (safe ∧ bounded_risk ∧ positive_expected, first_failing_reason(...))
```

# 7. Projections

## 7.1 State Projections

Applied to a single state (same as K3d):

```text
P.name : S → R
P.name(s) → value
```

## 7.2 Distributional Projections

Applied to a field of potential:

```text
P.name : Dist(S) → Dist(R)
P.name(d) = map(P.name, d)

// Convenience:
P.expected(f, d) = E[f, d]
P.variance(f, d) = E[f², d] - E[f, d]²
P.percentile(f, d, q) = ...
P.probability(pred, d) = Pr[pred(s) | s ~ d]
```

## 7.3 Projections and Invariants

| Concept | Type                      | Purpose                                   |
| ------- | ------------------------- | ----------------------------------------- |
| **N**   | `Dist(S) → Bool × String` | Validate the transformation (pass/fail)   |
| **P**   | `S → R` or `Dist(S) → R`  | Observe the transformation (read a value) |

N is the gatekeeper; P is the observer.

---

# 8. Output

Output (O) is a **derived concept**, not a primitive:

```text
O : (S × E × Dist(S)) → O*
```

Outputs are commands emitted *after* a transition for external execution. They are:

- **Post-causal:** Computed after Apply, not part of the causal step
- **Deterministic:** Same inputs → same output list
- **Replay-safe:** Skipped during replay (external effects not re-executed)
- **Distinct from projections:** P reads state; O emits commands

```text
Apply(s, e) → d
O(s, e, d) → [SendEmail(...), EnqueueJob(...), ...]
```

Outputs execute outside K3 semantics. The K3 system is causally complete without them.

# 9. Meta-Operators

## 9.1 Composition (<||>)

The **parallel composition** operator combines two K3 systems:

```text
(<||>) : K3 × K3 → K3

K3₁ <||> K3₂ = (S, S₀, E, G, T, N, P)
```

Where:

```text
S  = S₁ × S₂                             // Product state
S₀ = (S₀₁, S₀₂)                          // Product initial
E  = Left(E₁) | Right(E₂)                // Sum of events

G((s₁, s₂), Left(e₁))  = G₁(s₁, e₁)
G((s₁, s₂), Right(e₂)) = G₂(s₂, e₂)

T((s₁, s₂), Left(e₁))  = T₁(s₁, e₁) × δ(s₂)    // Product distribution
T((s₁, s₂), Right(e₂)) = δ(s₁) × T₂(s₂, e₂)

N(d) = N₁(marginal(d, π₁)) ∧ N₂(marginal(d, π₂))

P = {left.p: P₁.p ∘ π₁, right.p: P₂.p ∘ π₂}
```

Where `d₁ × d₂` is the product (independent) distribution: `(d₁ × d₂)(s₁, s₂) = d₁(s₁) · d₂(s₂)`.

Events in one universe do not affect the field of potential in the other (unless connected by a bridge).

## 9.2 Bridge (<->)

The **bridge** operator connects two systems with event propagation:

```text
(<->) : K3 × K3 × Mapper × BridgeMode → Bridge

Bridge = {
    source: K3₁,
    target: K3₂,
    mapper: (s_before: S₁, e: E₁, d_after: Dist(S₁)) → Option<E₂>,
    mode: BridgeMode
}

BridgeMode = Synchronous | Async | BestEffort
```

The mapper observes source transitions (including the full distributional result) and optionally emits target events:

```text
mapper(s_before, e, d_after) =
    Some(e₂)    // Emit event e₂ to target
    | None      // No propagation
```

**Note:** For deterministic systems, `d_after = δ(s_after)`, so the mapper effectively sees `(s_before, e, s_after)` — identical to the deterministic bridge signature.

### Bridge Modes

| Mode          | Semantics                                        | Use Case                   |
| ------------- | ------------------------------------------------ | -------------------------- |
| `Synchronous` | Target failure fails entire operation            | Transactional systems      |
| `Async`       | Target event queued, source succeeds immediately | Event-driven architectures |
| `BestEffort`  | Target failure logged but ignored                | Notifications, metrics     |

**Synchronous Bridge Apply:**

```text
BridgeApply_sync(s₁, s₂, e₁) =
    let d₁ = Apply₁(s₁, e₁) in
    if d₁ = ⊥ then ⊥
    else
        match mapper(s₁, e₁, d₁) with
        | None → (d₁, δ(s₂))
        | Some(e₂) →
            let d₂ = Apply₂(s₂, e₂) in
            if d₂ = ⊥ then ⊥
            else (d₁, d₂)
```

**Async Bridge:** An Async bridge is formally a composition of three K3 systems with Synchronous bridges — the source, an explicit Queue system, and the target. The queue is a full K3 system with its own state, events, guards, and invariants. See K3d specification for the canonical Queue encoding.

### Distribution-Aware Bridges

Bridges may inspect the distribution for cross-system decisions:

```text
mapper(s_before, e, d_after) =
    let risk = VaR(s → s.balance, d_after, 0.95) in
    if risk < -threshold then Some(RiskAlert(risk))
    else None
```

This enables bridges that trigger based on properties of the field of potential, not just individual outcomes.

## 9.3 Samsara (<?>)

The **samsara** operator provides simulation and testing:

```text
(<?>) : K3 × E* → RunResult

RunResult = {
    final: Dist(S) | S,            // Distribution or sampled state
    trajectory: (Dist(S) | S)*,    // Sequence of states/distributions
    traces: Trace*
}
```

**Samsara operations:**

| Operation      | Signature           | Description                   |
| -------------- | ------------------- | ----------------------------- |
| simulate       | E* → RunResult      | Run with trajectory           |
| reduce         | E* → Dist(S) or S   | Run without trajectory        |
| fuzz           | Config → Report     | Random event testing          |
| monte_carlo    | E* × ℕ × Ω → Report | Multiple sampled trajectories |
| property_check | Property → Result   | Property-based testing        |

# 10. Tracing

## 10.1 Design Principle

Traces are **non-interfering projections** over execution. A trace observes but never influences the causal step:

```text
Trace ⊥ Apply     // Tracing is orthogonal to causality
```

This means:

1. Removing all traces produces identical state evolution
2. Traces are replay-derivable — given the same events, same traces emerge
3. Traces may be discarded without loss of correctness

## 10.2 Traces Are Projections

Traces are a specific kind of projection over execution steps:

```text
TraceProjection : (S × E × Dist(S) × GuardResult × InvariantResult) → TraceRecord
```

Traces observe the full execution context — pre-state, event, resulting distribution, guard result, invariant result — and produce a record. They do not modify any of these values.

## 10.3 Formal Definition

```text
TraceRecord = {
    t: ℕ,                        // Logical time
    event: E,
    state_before: S,
    distribution_after: Dist(S),  // The field of potential
    state_after: Option<S>,       // The sampled state (if sampled)
    guard_result: (Bool, String),
    invariant_result: (Bool, String),
    metadata: Map<String, Any>
}
```

## 10.4 Tracing and Apply

```text
ApplyTraced(s, e) =
    let (g_ok, g_reason) = G(s, e) in
    let guard_result = (g_ok, g_reason) in
    if ¬g_ok then
        emit_trace(s, e, ⊥, guard_result, ⊥)
        ⊥
    else
        let d = T(s, e) in
        let (n_ok, n_reason) = N(d) in
        let inv_result = (n_ok, n_reason) in
        emit_trace(s, e, d, guard_result, inv_result)
        if ¬n_ok then ⊥
        else d
```

`emit_trace` is a projection — it observes but cannot affect the return value.

## 10.5 Design Invariants for Tracing

```text
1. Idempotent:     trace(trace(Apply)) ≡ trace(Apply)
2. Non-interfering: Apply_with_tracing(s,e) ≡ Apply_without_tracing(s,e)
3. Reproducible:   replay(events) produces identical traces
4. Discardable:    system correctness does not depend on traces
```

# 11. Manifestation & Replay

## 11.1 The Manifestation Problem

In the deterministic case (K3d), replay is straightforward: same events → same states. When distributions are non-trivial, the same event sequence produces the same field of potential at each step, but different manifestations (sampled states) depending on ω — the unmodeled causes.

K3 provides two forms of replay:

### Seeded Replay (Deterministic)

If ω is recorded alongside events, replay is deterministic:

```text
Replay(S₀, [(e₁, ω₁), (e₂, ω₂), ...]) → deterministic trajectory
```

This records the unmodeled causes that determined which potential manifested. Replay with the same ω produces identical results.

**Seeded Replay Equivalence Theorem:**

```text
∀S₀, ∀[(e₁, ω₁), ..., (eₙ, ωₙ)]:
    ReduceSampled(S₀, events, ω) is deterministic
```

Proof is by induction on event sequence length, using Axiom 1 (deterministic potential).

### Distributional Replay (Statistical)

Without recorded ω, replay produces the same *field of potential* at each step:

```text
Replay_dist(S₀, [e₁, e₂, ...]) → sequence of Dist(S)
```

The distributions are identical across replays (by Axiom 1). Only the sampled states may differ.

### Deterministic Replay (K3d Special Case)

When all distributions are points (`T(s,e) = δ(s')`), ω is irrelevant and replay is automatically deterministic:

```text
Replay(S₀, [e₁, e₂, ...]) → deterministic trajectory
```

This is the familiar K3d replay, and the most common case in practice.

## 11.2 Event Logging

K3 runtimes SHOULD log:

```text
EventLog_entry = {
    t: ℕ,                     // Logical time
    event: E,
    omega: Option<Bytes>,     // Recorded ω (omit for deterministic systems)
    sampled_state: S,         // The state that manifested
    timestamp: WallClock       // For operational use (not causal)
}
```

## 11.3 Invariant Replay

Because N validates the distribution *before* sampling, replay can verify:

1. That the field of potential at each step was valid: `N(d) = (true, _)`
2. That the sampled state was in the distribution's support: `d(s_sampled) > 0`
3. That ω correctly maps to the sampled state: `Sample(d, ω) = s_sampled`

The auditor verifies the *transformation* was valid, not just that the *outcome* was acceptable.

# 12. Verification

## 12.1 The Proof Obligation

Every K3 system must satisfy well-formedness:

```text
∀s ∈ S, e ∈ E:
    N(δ(s)) = (true, _) ∧ G(s, e) = (true, _) ⇒ N(T(s, e)) = (true, _)
```

This is a single check per (s, e) pair — the invariant evaluates one distribution, not each point.

## 12.2 Verification Strategies

| Strategy                   | Applicability              | Confidence          |
| -------------------------- | -------------------------- | ------------------- |
| **Property-based testing** | Any K3 system              | Probabilistic       |
| **Golden stream testing**  | Known-good event sequences | Regression          |
| **Inductive proof**        | Systems with structure     | Complete            |
| **Exhaustive (finite S)**  | Finite state/event space   | Complete            |
| **Coupling arguments**     | Monotone distributions     | High (mathematical) |
| **Martingale arguments**   | Conservation-like          | High (mathematical) |
| **Model checking**         | Finite/bounded state       | Complete (bounded)  |

### Property-Based Testing (Fuzz)

```text
fuzz_verify(K3, n_samples, confidence):
    violations = 0
    for i in 1..n_samples:
        s = random_valid_state()
        e = random_event()
        if G(s, e).ok:
            d = T(s, e)
            if ¬N(d).ok:
                violations += 1
    violation_rate = violations / n_samples
    return violation_rate ≤ (1 - confidence)
```

### Golden Stream Testing

```text
golden_test(K3, event_sequence, expected_final_state):
    actual = ReduceSampled(S₀, event_sequence, recorded_ω)
    assert actual = expected_final_state
```

### Inductive Proof

For systems with structured state:

```text
Base case:    N(δ(S₀)) = (true, _)
Inductive:    ∀s, e: N(δ(s)) ∧ G(s,e) ⇒ N(T(s,e))
Conclusion:   Invariant holds for all reachable states
```

## 12.3 Verification Templates

**Monotonicity:** A quantity never decreases (or increases).

```text
∀s, e: G(s,e) ⇒ E[f, T(s,e)] ≥ f(s)
```

**Conservation:** A quantity is preserved in expectation.

```text
∀s, e: G(s,e) ⇒ E[f, T(s,e)] = f(s)
```

**Ordering:** An ordering relation is preserved.

```text
∀s, e: G(s,e) ∧ sorted(s.list) ⇒ ∀s' ∈ support(T(s,e)): sorted(s'.list)
```

**State Machine:** Only valid state transitions occur.

```text
∀s, e: G(s,e) ⇒ ∀s' ∈ support(T(s,e)): (s.phase, s'.phase) ∈ allowed_edges
```

**Referential Integrity:** References remain valid.

```text
∀s, e: G(s,e) ⇒ ∀s' ∈ support(T(s,e)): ∀ref ∈ s'.refs: ref ∈ s'.targets
```

## 12.4 Decidable Fragments

Well-formedness is decidable for several useful fragments:

| Fragment             | N type                       | Decision Procedure     |
| -------------------- | ---------------------------- | ---------------------- |
| Finite state × event | Any computable N             | Exhaustive enumeration |
| Linear arithmetic    | Linear inequalities over ℤ/ℝ | SMT (Z3, CVC5)         |
| Monotonic systems    | f(s') ≥ f(s)                 | Induction + coupling   |

# 13. Extensions

K3 extensions add primitives to the 7-tuple without modifying the base semantics:

## 13.1 K3⁺ — Context Extension

Adds an 8th element `Ctx` (Context) for multi-tenancy, audit trails, and ambient information:

```text
K3⁺ = (S, S₀, E, G, T, N, P, Ctx)

Ctx includes: tenant_id, correlation_id, timestamp, actor_id
```

Context flows through the system but does not participate in causal transitions. It is metadata, not state.

## 13.2 K3ᵗ — Temporal Extension

Adds temporal/liveness properties to K3:

```text
K3ᵗ = (S, S₀, E, G, T, N, P, L)

L : Set<TemporalFormula>
```

Temporal operators over event-indexed traces:

- `◇φ` (Eventually): φ holds at some future point
- `□φ` (Always): φ holds at all future points — equivalent to K3 invariants
- `φ U ψ` (Until): ψ eventually holds, φ holds until then
- `□(φ ⇒ ◇ψ)` (Response): every φ is eventually followed by ψ

K3ᵗ adds **liveness** — "good things eventually happen" — to K3's **safety** — "bad things never happen."

See K3t.Calc.md for the full specification.

# 14. The Deterministic Case (K3d)

## 14.1 Definition

A K3 system is **deterministic** (K3d) when all transitions produce point distributions:

```text
∀s ∈ S, e ∈ E: T(s, e) = δ(s')    for some s' ∈ S
```

In this case, the field of potential has exactly one point. All causes have been modeled. There are no unmodeled variables, and ω is irrelevant.

## 14.2 Simplified Types

For K3d systems, the types simplify:

```text
T : S × E → S              // Returns a single state (via δ)
N : S → Bool × String       // Validates a single state (via δ)
Apply(s, e) → S ∪ {⊥}      // Returns a single state or rejection
```

These simplified types are obtained by composing with δ and the_single_state:

```text
T_det(s, e) = the_single_state(T(s, e))
N_det(s) = N(δ(s))
```

## 14.3 The Embedding

K3d embeds into K3 via point distributions:

```text
embed : K3d → K3
embed(S, S₀, E, G, T_det, N_det, P) = (S, S₀, E, G, T, N, P)
    where
        T(s, e) = δ(T_det(s, e))
        N(d) = N_det(the_single_state(d))    // d is always δ(s')
```

This embedding preserves all properties. K3d is a complete, self-consistent subset of K3.

## 14.4 When to Use K3d

| Scenario                                   | Recommendation | Reason                                    |
| ------------------------------------------ | -------------- | ----------------------------------------- |
| All causes are modeled                     | K3d            | No distributional reasoning needed        |
| Need strongest replay guarantee            | K3d            | No ω to record, replay is automatic       |
| State machines, CRUD, workflow, game logic | K3d            | Complete causal models                    |
| Simpler mental model for team              | K3d            | Point distributions add no value          |
| Need distributional invariants             | K3 (general)   | N on Dist(S) is genuinely more expressive |
| Need risk metrics (VaR, CVaR)              | K3 (general)   | Natural as N and P over distributions     |
| Significant unmodeled causes               | K3 (general)   | Distribution captures causal uncertainty  |
| Need convergence/mixing analysis           | K3 (general)   | Stationary distributions, coupling        |

Most practical systems are K3d. The full K3 is needed when the modeler explicitly chooses to leave causes unmodeled and reason about the resulting field of potential.

## 14.5 Full Specification

K3d has its own specification document (K3d.Calc.md) presenting the deterministic calculus with simplified types, deterministic replay, and all meta-operators in their K3d-specialized forms. Programmers building deterministic systems can work entirely within K3d without ever encountering distributions.

# 15. Compliance Levels

KC (Kulkarni Calculus) Compliance Levels define a formal standard for K3 implementations:

| Level    | Name                    | Core Capability                    | K3 Coverage              |
| -------- | ----------------------- | ---------------------------------- | ------------------------ |
| **KC-1** | Core Semantics          | State transitions with T → Dist(S) | S, S₀, E, G, T, N        |
| **KC-2** | Observable Semantics    | Projections and observability      | + P                      |
| **KC-3** | Traceable Semantics     | Simulation with replay guarantees  | + <?> (Samsara)          |
| **KC-4** | Compositional Semantics | Multi-system modeling              | + <\|\|>, <->            |
| **KC-5** | Verified Semantics      | Formal correctness proofs          | + Verification harness   |
| **KC-6** | Certified Runtime       | Regulatory-grade audit             | + Attestation (optional) |

### KC-1: Core Semantics

Implements the fundamental K3 operational semantics with guards and distributional invariants.

**Required:** S, S₀, E, G, T (→ Dist(S)), N (Dist(S) → Bool × String)

**Guarantees:** Deterministic potential (Axiom 1), guard-based admission, invariant-based transformation validation.

**Note:** KC-1 compliant systems may restrict to K3d (point distributions only) and still be fully compliant.

### KC-2: Observable Semantics

Implements KC-1 plus projections.

**Additional:** P (state projections), distributional projections (lifted P).

### KC-3: Traceable Semantics

Implements KC-2 plus Samsara (<?>) with replay guarantees.

**Guarantees:** Deterministic simulation, complete traceability, seeded replay fidelity.

### KC-4: Compositional Semantics

Implements KC-3 plus composition (<||>) and bridge (<->).

**Guarantees:** Algebraic composition, cross-system event propagation, configurable failure semantics.

### KC-5: Verified Semantics

Implements KC-4 plus formal verification.

**Required:** Property-based testing (fuzz), golden stream testing, invariant preservation verification.

**Optional:** Model checking, proof assistant integration, static analysis.

### KC-6: Certified Runtime

Implements KC-5 plus regulatory-grade audit.

**Note:** KC-6 is OPTIONAL and intended for regulated industries (aviation, finance, healthcare).

**Required:** Tamper-evident event log, ω recording for non-deterministic systems, attestation chain, formal well-formedness proof.

### Compliance Matrix

| Capability            | KC-1 | KC-2 | KC-3 | KC-4 | KC-5 | KC-6 |
| --------------------- | ---- | ---- | ---- | ---- | ---- | ---- |

# 16. Algebraic Properties

## 16.1 Composition Laws

```text
// Associativity
(A <||> B) <||> C  ≅  A <||> (B <||> C)

// Commutativity (up to isomorphism)
A <||> B  ≅  B <||> A

// Identity
A <||> Unit  ≅  A
    where Unit = ({()}, (), {}, λ_.true, λ_.δ(()), λ_.true, {})
```

## 16.2 Reduction Laws

```text
// Empty reduction
Reduce(d, []) = d

// Associativity over concatenation
Reduce(d, E₁ ++ E₂) = Reduce(Reduce(d, E₁), E₂)

// Deterministic case:
ReduceDet(s, E₁ ++ E₂) = ReduceDet(ReduceDet(s, E₁), E₂)
```

## 16.3 Safety Laws

```text
// Invariant preservation (well-formedness)
N(δ(s)) ∧ G(s,e) ⇒ N(T(s,e))

// Invariant induction
N(δ(S₀)) ∧ (∀s,e: N(δ(s)) ∧ G(s,e) ⇒ N(T(s,e))) ⇒ ∀ reachable s: N(δ(s))

// Guard safety
¬G(s,e) ⇒ Apply(s,e) = ⊥

// Composition preserves invariants
N₁(δ(s₁)) ∧ N₂(δ(s₂)) ⇒ N_composed(δ(s₁, s₂))
```

## 16.4 Distribution Laws

```text
// Monad laws (bind is associative with δ as unit)
bind(δ(s), f) = f(s)                           // Left unit
bind(d, δ) = d                                  // Right unit
bind(bind(d, f), g) = bind(d, λs. bind(f(s), g))  // Associativity

// Distribution determinism
T(s, e) = T(s, e)    // Same inputs, same distribution (Axiom 1)

// Point distribution collapse
N(δ(s)) reduces to checking single state s
```

## 16.5 Trace Laws

```text
// Non-interference
Apply_traced(s, e).state = Apply(s, e).state

// Reproducibility
trace(Replay(E*)) = trace(Replay(E*))

// Discardability
correctness(system) does not depend on trace collection
```

## 16.6 Category-Theoretic Structure

K3 systems form a **symmetric monoidal category**:

- **Objects:** K3 systems
- **Morphisms:** Bridges (event-propagating maps between systems)
- **Tensor product:** <||> (parallel composition)
- **Unit:** The trivial K3 system

# 17. Expressiveness & Limitations

## 17.1 What K3 Can Express

Any discrete causal system with decidable predicates:

- State machines (finite or infinite state)
- Event-sourced systems
- Workflow/saga orchestration
- Protocol specifications
- Game mechanics
- Physical simulations (discretized)
- Financial models (with distributional transitions)
- Population dynamics
- Queuing systems
- Any system expressible as (state, event) → distribution over next states

## 17.2 Turing Completeness

K3 is Turing-complete. Lambda Calculus encodes as a K3 system:

```text
S = { term: LambdaTerm, reduced: Bool }
E = BetaReduce
G(s, BetaReduce) = (has_redex(s.term) ∧ ¬s.reduced, "No redex or already reduced")
T(s, BetaReduce) = δ({ term: reduce_leftmost(s.term), reduced: ¬has_redex(reduce_leftmost(s.term)) })
N(d) = (true, "")    // No invariant needed for computation
```

## 17.3 What K3 Does Not Natively Model

| Concept                     | Why Not Native        | Modeling Strategy         |
| --------------------------- | --------------------- | ------------------------- |
| Continuous time             | K3 uses logical time  | Tick events + integration |
| Liveness properties         | K3 is safety-oriented | K3ᵗ extension             |
| Higher-order transitions    | T is fixed            | Rules as state            |
| Concurrent event processing | Apply is sequential   | Composition (<\|\|>)      |
| Continuous distributions    | K3 is discrete        | Discretization            |

## 17.4 Expressiveness Relationship

```text
FSM ⊂ LTS ⊂ K3d ⊂ K3

Petri Nets ≅ K3d (with appropriate encoding)
Event Sourcing ⊂ K3d (K3 adds guards + invariants + composition)
Actor Model ~ K3 <||> + <-> (composition + bridges)
```
